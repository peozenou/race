# Tennis data audit

Determine whether the requested scope is trustworthy enough for its intended use. Default read-only: an audit request does not authorize repairs, publication or sharing junior data. For weekly Race, race-audit owns phase 2 and Patrick's approval of the exact sealed candidate after source/summary checks. Read the [shared contract](../update-the-race/references/run-contract.md) and [Race audit scope](../update-the-race/references/audit-contract.md). New runs have four phases and no email task.

Resolve decision/scope, season/Monday/competition week/cutoff, versions and evidence once. Inspect immutable primary hashes, source/capture/event/as-of dates, canonical mappings, exact diffs/authorization, backups and relevant fresh native values/formulas/formats. A candidate matching its own proposed payload is not a primary-source audit.

Verify identities/views/pages/schema/keys and genuine empty-source evidence before values. Independently compare every required field, blank/type, row order, missing/extra/duplicate, exclusion and coverage denominator. Use representation-only numeric tolerances; never round away disagreements or replace missing visible statistics with hidden data/zero.

For Race cover complete selected TA B:X input scope, TE pages/tails and 60 joins, roster/transfers, independent +5 duel identities, five team paths/deltas, snapshot/week/cutoff, native formula/table extent and protected history. Separate active selections from retained outgoing public rows. Reuse checks only with all dependencies unchanged; prove initial/changed history baselines fully and routine bounded deltas before sealing. A later volatile LIVE outage does not invalidate an unchanged sealed release; genuine frozen corrections create linked revisions and affected review.

Elo/UTR/MatchTrack audits are independent and only included when in scope. Elo means both complete reports and true dates; UTR comes from Patrick, never scraping. MatchTrack means real schemas, logical revisions/duplicates, scoring/final-score and coverage/context. Analytical audits also check grain, denominators, available-at timing, leakage and reproducibility. Read [detailed checks](references/audit-checks.md) only for relevant modules.

Each check names expected/observed scope/counts, evidence/digests, discrepancies, PASS/QUALIFIED/FAIL/NOT_CHECKED/BLOCKED, consequence and next action. Required missing/failed coverage cannot pass; partial comparisons are not complete consistency. A bounded qualification explains its effect. Missing private input or no independent Elo advance never blocks unrelated Race output.

Persist a report/exception register tied to the candidate/release digest. Route a repair to its owning writer with a concrete diff and applicable scope: an already authorized routine profile recovery needs no repeated permission; an out-of-profile history/rule/schema change needs a specific decision. Repeat affected checks and preserve prior evidence. A report alone is not Patrick's release approval. Requested figures remain separate; the routine weekly flow adds no PNG or Gmail requirement.
