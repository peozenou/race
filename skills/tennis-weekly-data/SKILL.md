# Tennis acquisition and readiness

For weekly Race execution use update-the-race: Collect → Validate and review → Release and hand over → Claude publish/live verification. New runs end there, with no email task. Race has two routine decisions: Start under the bounded profile and approval of the exact frozen candidate. Read the [shared contract](../update-the-race/references/run-contract.md) and [adapter inventory](../update-the-race/references/adapters.md).

A readiness/acquisition-only request produces immutable evidence, typed candidates, scoped checks and the next action. It does not authorize Sheet writes, release, production or automatic Claude dispatch. Use race-check-ready for the Sunday/Monday watch; its source/access and actual iPhone pilot must pass before scheduling activation. Notification delivery does not approve Start.

Reuse the resolved season/Monday/competition week/cutoff/roster and exact private run. Competition week is not ISO week. Read current source/specification context and preserve it read-only. Prefer the specific module's reviewed adapter; do not run a stale all-module launcher, invent selective flags or claim Mac/browser control without observed access.

Save primary bytes before normalization, with hashes, URLs/identities, actual publication/capture/event/as-of dates, schema/version and null reasons. TA displayed Serve/Return owns stats/blanks; complete TA Elo/yElo reports own ratings; TE owns ranking publications; Patrick supplies private UTR. Respect source restrictions, cooldowns and bounded retries. A blocked/error page is not an empty season. Preserve diagnostics and stop affected structural/identity failures.

Use a fresh durable private run for a new week. Exact resume verifies code/config/roster/raw/checkpoint digests, lock ownership and cooldown. Do not edit old raw evidence to force resume. Logical keys distinguish revised exports from new observations; two player perspectives are not two contests. MatchTrack requires actual header/schema, score progression, final-score and coverage/context checks, not invented server or rally tags.

Elo + yElo and private UTR remain independent weekly lanes; read [lane routing](../update-the-race/references/independent-lanes.md). Consolidate pending UTR input into the owner intake only when not already supplied. Missing private input or unchanged/delayed independent Elo does not block Race. A later rating import never silently changes a sealed Race snapshot.

Persist inventories, candidate/preview inputs, coverage denominators, exceptions and exact resume action. PASS/QUALIFIED/FAIL applies only to executed scope. Capture or parsing success is not source-audited release or approved write evidence. Handoff to the owning module for profile/prestate/backup/readback and separate release approval. See the [portable acquisition contract](references/acquisition-contract.md).
