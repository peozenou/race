# Proposed standard weekly write profile

Status: pending approval and implementation. The private installed profile will bind the exact workbook ID, native sheet IDs, roster/rule/transfer versions and season. Public documentation does not contain that private configuration. Each Start names the profile version, competition week and exclusive cutoff; it is not blanket permission to edit any workbook.

## Routine authorized scope after approval

| Area | Allowed operation | Protection boundary |
|---|---|---|
| Current active player tabs | Insert genuinely new eligible current-season match rows and correct primary-source differences in B:X. Fill the existing result/duel formulas and copy the verified exemplar formatting for inserted rows. | No old-year input rewrite, archived-player refresh or scoring-rule alteration. Preserve legitimate native reference shifts and prove protected history. |
| LIVE rankings | Refresh the existing Race/ATP IMPORTHTML anchors and their source-date notes, using the same verified URL/table/page mappings. | No arbitrary formula replacement, invented zero or unverified page mapping. Restore only after immutable source capture. |
| Weekly snapshot | Create one correctly dated/week-named snapshot, freeze its raw and reviewed derived values, retaining source identity/date evidence. | Never overwrite an older frozen week. Existing same-run snapshots require exact prestate reconciliation rather than duplication. |
| HEBDO | Append the current competition-week row once, with five frozen Race/Duels/Total paths and verified formatting. | Prior rows remain unchanged; duplicate week is an error. |
| JOUEURS | Append the current weekly contribution column once; extend the existing native table/format range and preserve legitimate sparkline reference extension. | No recasting outgoing-player history, dropping old columns or changing metric definitions. |
| BILAN and current derived blocks | Update the explicit current-week ranking/contribution selectors and current derived source notes. Recompute and independently reconcile 30 player paths, five totals and 55 TEAMS outputs. | Preserve unrelated formulas, formatting, archived data and the transfer ledger. A rule/formula repair outside these selectors is a specific exception. |
| Routine source outage recovery | At most one automatic clear/restore attempt per unchanged existing import anchor and source epoch, after backup/prestate checks. Verify the exact intended values and complete affected dependencies. | No changed URL/source date/rule, no repeated retry loop, no history patch. Stop on a source challenge, changed values or failed bounded retry. |
| Public release | After separate approval of the exact candidate hash, publish the six existing datasets coherently on a dedicated data branch; verify all six hashes. | Calendar/colors remain byte-identical unless separately reviewed. No private files, schema expansion, production push or unrelated source/design changes. |

One verified whole-workbook backup before the first logical weekly write, plus lossless local prestate/delta evidence, replaces repeated whole-workbook copies at every submodule. A later expanded mutation needs another appropriately scoped backup. Verify readback and protected dependencies before proceeding; a successful API response alone is insufficient.

## Always require a specific decision

New roster membership, scoring/transfer semantics, an unknown entry baseline, archived or prior-year corrections, changed source authority, expanded public schema/destination, nonroutine structural changes and materially changed exceptions. Group related questions into one concrete decision with source evidence and impact.

The routine profile does not authorize a public release before its final approval, triggering Claude automatically, changing a sealed release in place, email work, private-data publication, paid services or Apple enrollment.

## Configuration and versioning

Record a profile digest, exact generated diff, primary-source manifests, backup references, write batches and independent readback. Changed profile permissions require explicit review. The Start approval and final release approval are different records.

This document is a reviewable scope definition. The new runner, exact private configuration and source adapters still need implementation and tests after design approval; documentation alone does not make them operational.
